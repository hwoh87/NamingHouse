# 이름 통계 표본 수집기

법원 통계서비스의 **지역별 상위 이름 표본**을 합산해 `engine/src/main/assets/name-stats.tsv`와 `name-stats-metadata.properties`를 함께 만든다. Python 3.9 이상 표준 라이브러리만 사용한다.

출처: [대한민국 법원 전자가족관계등록시스템 · 상위 출생신고 이름 현황](https://stfamily.scourt.go.kr/st/StFrrStatcsView.do?pgmId=090000000025)

## 자료의 범위

- 기존 조회 프로필은 16개 지역 × 2개 성별 × 연도별 요청이다. 각 응답의 상위 20개 이내 이름을 합산하며 전국 전체 출생신고 건수가 아니다. 지역 코드의 시대별 행정구역 포괄성은 별도 검토가 필요하다.
- 특정 성별의 0건은 **이 표본에서 확인되지 않음**을 뜻한다. 실제 사용자가 없거나 해당 이름의 정확한 성별 비율이 100%라는 뜻이 아니다.
- 합산 대상은 한글 1~3음절이다. 순위는 합산 표본에서 다시 계산하고, 동일 건수는 이름순으로 정렬한다. 이력은 최근 조회 6개 연도, 누적 건수가 우세한 성별 기준이다.
- **조회 연도**, **원본을 실제 받은 날짜**, **원자료의 집계 종료일**은 서로 다르다. 요청 성공이나 파일 생성 날짜로 원자료 종료일을 추정하지 않는다.
- 기존 번들은 213개 이름, 조회 연도 2008~2026이다. 당시 수집일/원자료 집계 기간/요청 성공 기록이 없어 메타데이터에 `unknown`, `legacy_unverified`로 기록했다. 파일 수정 시간이나 이번 검토일로 소급 작성하지 않았다.

## 안전한 실행

```bash
# 원본 캐시가 없거나 갱신이 필요한 요청만 수행한다.
python3 tools/name-stats/build_name_stats.py

# 올해 응답은 다시 확인하고, 과거의 유효한 버전 캐시는 재사용한다.
python3 tools/name-stats/build_name_stats.py --refresh-current-year

# 네트워크를 전혀 사용하지 않고 검증된 캐시만 사용한다.
python3 tools/name-stats/build_name_stats.py --offline

# 회귀검증: 가짜 응답과 임시 디렉터리만 사용한다.
python3 -m unittest discover -s tools/name-stats -p 'test_*.py' -v
```

현재 연도는 실행 환경 기준이며 기본 조회는 2008년부터 현재 연도까지다. `--start-year`/`--end-year`로 연속 구간을 지정할 수 있다. 현재 연도보다 미래인 범위는 거절한다. 요청 간 0.4초 쉬며 타임아웃은 60초다. 현재 연도 캐시도 명시적 갱신 옵션이 없으면 재사용하므로, 수집일과 조회 연도를 함께 확인한다.

**모든 요청이 성공하고 검증을 통과해야 번들을 발행한다.** 일부 요청 오류, 누락된 `data`, 잘못된 숫자/행, 중복 이름, 해시 불일치, 빈 결과를 조용히 건너뛰지 않는다. 실패하면 기존 TSV와 메타데이터를 유지한다. 실패 전에 받은 유효한 개별 캐시는 다음 재시도에 쓸 수 있다. 오류 원인을 해결하거나 `--refresh-all`로 캐시를 다시 조회할 수 있다.

빈 배열은 실제 자료 없음과 세션 만료를 구분할 수 없으므로 기본적으로 실패한다. 필요한 빈 결과를 원본 화면 등으로 확인한 뒤 아래 형태의 검토 파일을 `--empty-allowlist reviewed-empty.json`에 지정한다. 검토하지 않은 쿼리를 일괄 허용하면 안 된다.

```json
{
  "schemaVersion": 1,
  "queries": {
    "2008_36_1": "검토한 근거와 실제 확인일을 여기에 기록"
  }
}
```

위 키는 형식 예시이며 실제 빈 데이터가 확인되었다는 뜻이 아니다. 승인 목록은 정확한 연도_지역_성별 키에만 적용한다. 기록 없는 구형 배열 캐시는 `--allow-legacy-cache`를 명시해야만 재사용하고, 스키마 검증 및 빈 결과 검토는 동일하게 요구한다. 이 경우 실제 수집 기간을 알 수 없으므로 번들에 미기록으로 남긴다.

## 캐시와 발행 보장

`raw/<year>_<sido>_<gender>.json` 새 캐시는 다음 정보를 갖는다.

- `cacheSchemaVersion=1`, `querySchemaVersion=1`
- 조회 URL과 정확한 연도/지역/성별
- 실제 응답을 받은 UTC `fetchedAt`
- 원본 `rows`와 정규 JSON의 `rowsSha256`
- 허용된 빈 결과는 `emptyReviewReason`

출처, 조회 식별자, 버전, 날짜, 행, 체크섬을 모두 확인한다. 원자료의 동순위는 유효하므로 중복 순위값을 거절하지 않는다. 캐시를 임시 파일에 쓰고 `fsync` 후 같은 디렉터리에서 원자적으로 교체한다. 잘못된 새 응답이 기존 캐시를 덮어쓰지 않는다.

TSV와 메타데이터도 임시 파일에 모두 기록한 뒤 각각 원자적으로 교체한다. 일반 I/O 실패 시 이전 파일로 되돌린다. **두 파일을 한 번에 원자적으로 교체하는 구조는 아니다.** 프로세스 종료/전원 중단으로 중간 상태가 남으면 앱이 메타데이터의 `datasetSha256`과 원본 TSV 바이트를 대조해 잘못된 조합을 거절한다. 검증되지 않은 일부 자료를 정상 통계로 표시하지 않는다. 동시에 여러 수집기를 실행하지 않는다.

## 출력과 로더

| TSV 필드 | 의미 |
|---|---|
| `name` | 한글 1~3음절 이름 |
| `dominant` | 표본 누적 건수가 우세한 성별 M/F (같으면 M) |
| `maleCount`, `femaleCount` | 조회 범위에 있는 지역별 상위 이름 표본의 합 |
| `ranks` | 최근 조회 6개 연도의 표본 순위 `연도:순위`; 없으면 빈 값 |

메타데이터는 버전, TSV SHA-256, 조회 연도/지역 코드, 최대 응답 행 수, 수집 기간, 원자료 기간, 요청 수, 이름 수를 기록한다. `generatedAt`은 파일을 만든 시점으로 수집일과 다르다. `complete_query_set`은 **지정된 모든 조회의 응답을 검증했다**는 뜻이며 전국 모든 신고를 포괄했다는 뜻이 아니다. 기존 파일의 `successfulRequestCount=unknown`은 알 수 없는 성공 건수를 608건으로 채우지 않은 것이다.

Android에서는 `NameStatsMetadata.parse(lines)` 이후 `NameStats.parse(bytes, metadata)`를 사용한다. 원본 바이트를 기준으로 해시를 확인하며, 헤더·숫자·합계 범위·성별·중복 이름·중복 연도·조회 범위 밖 순위를 거절한다. `parse(lines, metadata)`는 UTF-8/LF 및 마지막 개행의 생성기 표준을 기준으로 해시를 계산하므로 실제 assets에는 바이트 API를 권장한다.
